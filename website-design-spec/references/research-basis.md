# Research basis and portability

Research checked 13 November 2026. These are methodological sources, not evidence about an audited site. No source can establish an unseen site's specific design choices. Recheck evolving tool/installation guidance when adapting to a new host.

## Skill engineering: sources → decisions

1. [Agent Skills specification](https://agentskills.io/specification). Defines the portable directory/frontmatter model and progressive disclosure. **Applied:** short discoverable metadata, concise entry point, relative supporting references, optional scripts. The skill uses common fields rather than Claude-only invocation syntax in its executable workflow.
2. [OpenAI: Build skills](https://developers.openai.com/plugins/build/skills). Describes workflow boundaries, inputs/outputs, uncertainty, resources, and packaging. **Applied:** one focused extraction task, explicit deliverables, capability checks, no implicit website construction/publication.
3. [OpenAI: Rethinking skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra). Advises removing bloated/overlapping routing instructions. **Applied:** narrow description, no broad mandate to activate on all frontend tasks, detailed design knowledge in references.
4. [Claude: Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices). Covers context economy, appropriate specificity, progressive resources, real evaluations, and iteration. **Applied:** method/format/checklist split, concrete evidence labels, behavioral scenarios and cold-context testing. The skill does not mechanically impose a rigid workflow on all websites.
5. [OpenAI: Testing skills systematically](https://developers.openai.com/blog/eval-skills). Frames validation as observable agent behavior beyond linting. **Applied:** structural checks plus a fresh-agent website run and review of actual artifacts. A single test is not a general reliability benchmark or proof of improvement over a baseline.
6. [Gemini CLI: Creating skills](https://geminicli.com/docs/cli/creating-skills/), [skill best practices](https://geminicli.com/docs/cli/skills-best-practices/), and [managing skills](https://geminicli.com/docs/cli/using-agent-skills/). Document compatible structure/discovery, progressive context loading, appropriate degrees of freedom, deterministic helpers, and concise script output. **Applied:** tool-neutral instructions, environment checks, parameterized collection, compact stdout, and no hard dependency on one vendor's browser namespace.
7. [Claude Code: Skills](https://code.claude.com/docs/en/skills). Documents discovery and platform-specific frontmatter/extensions. **Applied:** common `name`/`description` entry point; Codex UI metadata remains separate in `agents/openai.yaml` and is not needed for core execution.

## Design extraction: sources → dimensions

8. [NN/g: Visual design principles](https://www.nngroup.com/articles/principles-visual-design/). Connects composition to scale, hierarchy, balance, contrast, and perceptual grouping. **Applied:** philosophy must connect visible choices to patterns, rather than rely on aesthetic adjectives.
9. [NN/g: Ten usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/). Provides a framework for status feedback, consistency, control, recognition, errors, and help. **Applied:** inspect actual task paths and component feedback, including untested/error states; do not equate attractive visuals with proven usability.
10. [web.dev: Responsive design course](https://web.dev/learn/design/). Covers macro/micro layout, type, media, internationalization, theming, input, and accessibility. **Applied:** compare multiple widths, input types, image crops, and content order; do not reduce responsiveness to a scaled desktop screenshot.
11. [MDN: getComputedStyle](https://developer.mozilla.org/en-US/docs/Web/API/Window/getComputedStyle). Explains resolved styles, pseudo-elements, serialization, and privacy limits. **Applied:** capture exact active styles and distinguish authored declarations from viewport/state-specific resolved values. Do not claim visited-state verification from computed styles.
12. [MDN: CSS Font Loading API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Font_Loading_API). Documents font readiness and face lifecycle. **Applied:** await fonts with a bound; distinguish declared, available/loaded, and actually rendered glyph fonts.
13. [MDN: Document.getAnimations](https://developer.mozilla.org/en-US/docs/Web/API/Document/getAnimations). Exposes active CSS transitions/animations and Web Animations. **Applied:** collect timing/keyframes where possible, while acknowledging missing past, script-driven, and canvas motion.
14. [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion). Describes user-preference media behavior. **Applied:** compare actual reduced-motion rendering; an authored query alone is insufficient behavioral evidence.
15. [Design Tokens Community Group: Format 2025.10](https://www.designtokens.org/tr/2025.10/format/) and [Color module](https://www.designtokens.org/tr/2025.10/color/). Specify exchange types, aliases, grouping, and color spaces. **Applied:** distinguish primitive/semantic/component relationships, preserve units/color spaces, and avoid falsely labeling a custom audit JSON as conformant DTCG. DTCG is a Community Group report, not a W3C Recommendation.
16. [W3C: WCAG 2.2](https://www.w3.org/TR/WCAG22/). Normative accessibility requirements. **Applied:** scoped inspection of semantics, input, focus, contrast, reflow, timing, motion, and resilience without claiming certification.
17. [WAI: Contrast minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Explain threshold application and exceptions. **Applied:** measure actual foreground/backing pairs, separate text/UI checks, preserve uncertainty for gradients/transparency.
18. [WAI: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html). Explains 320 CSS px and zoom-related behavior. **Applied:** add a narrow-width reflow check and avoid treating a normal mobile screenshot as a complete zoom audit.
19. [WAI: Target size minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Explains 24px minimum with spacing and exceptions. **Applied:** do not confuse AA minimum with the enhanced 44px target or call failures from box size alone.
20. [WAI: Animation from interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html). Explains the AAA criterion for disabling nonessential interaction animation. **Applied:** audit motion preferences without presenting every missing reduced-motion effect as an AA failure.
21. [web.dev: Web Vitals](https://web.dev/articles/vitals). Explains LCP/INP/CLS and field assessment. **Applied:** separate perceived performance, local lab data, and real-user evidence; no fabricated scores or causal claims.

The checklist and evidence contract are a synthesis of these sources. Exact sampling sizes, filenames, evidence labels, and the observation JSON are practical conventions of this skill, not requirements imposed by those standards. Material's motion overview was also consulted but its text required JavaScript; no timing defaults or site-specific rules were taken from it.

## Cross-agent use

The folder's core is ordinary Markdown, YAML, and optional Node.js. Use the same folder in a supported skills directory, or explicitly ask an agent to read its `SKILL.md` by path. A compatible file format does not guarantee identical tool access, permission behavior, invocation, or execution quality.

- **Codex in this environment:** installed at `~/.codex/skills/website-design-spec`; invoke `$website-design-spec` or reference the path. `agents/openai.yaml` supplies UI metadata. Confirm the host's current discovery locations before installing elsewhere; [official Codex skills documentation](https://developers.openai.com/codex/skills/) is the canonical reference.
- **Claude Code:** user skills conventionally use `~/.claude/skills/<name>/SKILL.md`, project skills `.claude/skills/<name>/SKILL.md`; verify against the linked Claude Code docs. No Claude-only hooks, substitutions, or subagent requirements are embedded.
- **Gemini CLI:** user/workspace `.gemini/skills/` locations and `.agents/skills/` aliases are documented in the linked management guide. Retain the complete relative reference/script tree.
- **Other agents:** requires compatible skill discovery or explicit file loading, browser access for visual claims, and writable outputs for file delivery. Without a browser, the correct behavior is a limited result, not invented design details.

Only report platforms actually exercised. Installing into Claude/Gemini is separate from creating the portable folder; do not modify their settings without a request. Host-specific permission rules and the user's scope always govern tool use.
